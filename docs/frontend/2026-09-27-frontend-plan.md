Primary task: run a supported airport analysis, compare the returned values, and understand what its evidence does and does not establish.

Seven governing rules:

1. **The answer leads.** Selected metric, population and period accompany the result; provenance and limitations remain reachable without competing with the answer. Material caveats are never hidden behind decorative emphasis.
2. **Geometry preserves meaning.** Backend airport/rank order stays authoritative, like units align, and related metrics stay grouped. A large value is never visually promoted into a favorable investment recommendation.
3. **State is truthful and local.** Use `/state-coverage-audit` as the coverage owner; actual draft, request and returned-result state drives feedback. Preserve the existing partial/previous-result distinctions. A timer, animation or health response cannot establish analytical success or model readiness.
4. **Completion does not take over reading.** Provide a visible, keyboard-accessible View result action when output is elsewhere; do not automatically move focus or scroll merely because a response arrived. Activate that action to navigate deliberately. Draft changes cannot replace the result being read with a stale response.
5. **Actions have a clear hierarchy.** Emphasize the current analysis action; Explain, reset, extra examples and advanced scope remain supporting controls. A disabled capability remains disabled after loading ends.
6. **Typography supports comparison.** Use a few semantic text roles, restrained ink/weight hierarchy, tabular figures and readable prose width. Tables keep the width they need; long explanations do not span that entire width.
7. **Responsive behavior preserves the task.** Keyboard, narrow viewport, zoom and reduced motion retain the same meaning and recovery actions. Composer growth and status changes must not obscure the active work.

Apply the rules to existing state rather than add another store: the draft belongs to form controls, `busy` represents an in-flight request, `requestGeneration` invalidates stale responses, and `latestSuccessfulResult`/`contextResultId` retain accepted output/context. An explicit unavailable-free-text flag is capability state, not loading state. Server-returned values/provenance remain authoritative. Preserve a question draft through errors and preset/Explain actions; an explicit Start new analysis may clear it. Do not add browser persistence of questions. Keep native textarea Enter as newline; do not add send-on-Enter or intercept IME composition.

Typography preflight found system-ui, existing page/section/subheading sizes, primary/secondary ink, emphasized labels, `75ch` prose, and tabular table numerals. Reuse those working choices. Step 16 names the roles (page, section, body, label, metric, diagnostic), mapping roles to shared values where appropriate; it does not introduce six mandatory sizes, a downloaded font, or a separate design-system package. Bound a future editable composer's growth to the available viewport with internal scrolling; test long drafts and keyboard-open behavior when editing is enabled.

Performance rule: only if a performance change is proposed, record the same route/action, frontend hash, backend revision/bundle, browser/host/device class/viewport and cache conditions before and after. Inspect page-load and one representative query path; separate request duration from rendering/interaction work. Reproduce the delay in comparable repeated local runs and identify its dominant cause. Before editing, declare the measurement protocol, success threshold and regression limits, justified by that baseline or a product requirement. Change one cause, then keep or revert against those predeclared conditions plus correctness checks. Local lab measurements are not field p75 evidence; field metrics remain unavailable. The observed offscreen feedback problem is a UX defect, not evidence of backend latency. `changedDraft()` currently rebuilds the previous result on input; profiling may inspect that path, but no rendering cost has been measured. Do not debounce typing, add caching/virtualization, strip source metadata or alter the API speculatively. Refer a proven backend bottleneck to its owner.

## Acceptance criteria

1. A completed request makes its status and result discoverable by sight and keyboard; a late response never steals focus from a user editing a new draft.
2. Unused long-haul input cannot block other metrics. Known invalid scope combinations receive field-linked guidance before a request.
3. Busy, expired-session, mismatch, invalid-scope, unavailable-AI and network failures retain the prior result with the appropriate next action and no retry.
4. Historical results retain correct units, ordering, scope, sources and partial semantics. Recent results render only under the finalized backend contract, including resolved period/bundle provenance.
5. Desktop and 390px layouts keep controls usable, tables contained, focus visible and limitations readable; meaningful state tests and browser acceptance pass.
